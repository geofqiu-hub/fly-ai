# FlyAi 剩余功能开发详细计划

本项目已完成基础架构（IPC, SQLite）和 Gemini 基础对话集成。以下是后续核心功能的详细实施计划。

---

## Phase 3: 智能体 (Agent) 管理系统
**目标**：允许用户创建具有特定行为、提示词和配置的 AI 角色。

### 1. 数据模型与存储
- [ ] **Agent 表扩展**：确保 `agents` 表支持 `system_prompt`, `model_id`, `temperature`, `avatar_color`, `description` 等字段。
- [ ] **关联关系**：在 `sessions` 表中存储 `agent_id`，实现对话与智能体的绑定。

### 2. UI 界面开发
- [ ] **Agent 列表页**：在 Settings 中实现 Agent 的 CRUD。
- [ ] **Agent 编辑器**：支持实时预览头像颜色，多行输入 System Prompt。
- [ ] **Agent 选择器**：在输入框上方或侧边栏提供快速切换 Agent 的组件。

### 3. 功能集成
- [ ] **预设模板**：内置 3-5 个常用 Agent（如：代码审查专家、翻译官、周报撰写助手）。
- [ ] **自动标题生成**：新对话第一句话后，由特定 Agent 总结生成对话标题。

---

## Phase 4: 多模态 (Multimodal) 支持
**目标**：发挥 Gemini 的长处，支持图片、文档、视频（未来）的理解。

### 1. 前端交互
- [ ] **文件拖拽/选择**：在 InputArea 实现文件添加功能。
- [ ] **预览列表**：发送前在输入框上方显示缩略图，支持删除。
- [ ] **消息渲染**：在 `ChatArea` 中实现 `ImagePart` 渲染。

### 2. 后端处理
- [ ] **Base64 转换**：将用户上传的文件转为 Gemini SDK 要求的 `inlineData` 格式。
- [ ] **存储策略**：本地临时缓存上传的文件。

---

## Phase 5: 对话压缩技术 (Session Compaction)
**目标**：学习 opencode 经验，解决长对话 Token 溢出和 API 成本问题。

### 1. 核心算法 (主进程)
- [ ] **触发器**：监听消息发送，当 Token 估算值 > 100k 时触发。
- [ ] **8 段式摘要**：学习 opencode 的结构化摘要。
- [ ] **智能边界选择**：保留最近 N 个回合（Turn），其余部分压缩。

### 2. UI 呈现
- [ ] **压缩消息组件**：在聊天流中显示“N 条消息已压缩”的折叠卡片。
- [ ] **状态提示**：正在压缩时的后台状态展示。

---

## Phase 6: 知识库 (Knowledge Base / RAG)
**目标**：支持本地文档作为 AI 的上下文参考。

### 1. 数据处理
- [ ] **文档解析**：支持 PDF, Markdown, TXT 解析。
- [ ] **向量化预留**：预留 `embeddings` 存储字段。
- [ ] **切片管理**：实现文档 Chunking。

### 2. 集成对话
- [ ] **参考引用显示**：AI 回复时展示参考了哪些本地文档片段。

---

## Phase 7: 云端同步与数据安全
**目标**：预留云端同步能力，确保用户跨设备数据一致。

### 1. 架构预留
- [ ] **数据全量导出**：一键生成加密的对话/配置 JSON。
- [ ] **Sync Queue**：实现增量同步操作记录表。
- [ ] **API 预留**：代码中预留 `uploadUserData` 接口占位。

---

## Phase 8: 多模型厂商接入
- [ ] **OpenAI Provider**：实现基础对话与 GPT-4o-mini 压缩。
- [ ] **GLM / Qwen Provider**：针对国产大模型进行适配。
- [ ] **统一模型面板**：支持跨厂商模型横向对比选择。

---

## 🔧 紧急优化清单 (UI/UX)
- [ ] **Markdown 重新修复**：解决 `className` 报错，恢复优美的 Prose 排版。
- [ ] **流式打字机效果**：优化渲染逻辑，让文字逐个跳出。
- [ ] **Session 标题即时编辑**：侧边栏支持双击修改标题。
